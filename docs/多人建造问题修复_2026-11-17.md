# 多人建造问题修复 · 2026-11-17

后续发布：三个修复已于同日随[0.4.1](0.4.1_发布记录_2026-11-17.md)部署到正式服并加入安装包/在线更新。以下保留此前仅推送阶段的修复和专项验证记录。

本次只修复、验证和推送源码，未导出、发布或部署，版本号仍为0.4.0/build7/协议4。正式服和已下载的安装包不包含本次修复。真实角色、登录信息、偏好与地皮进度未读写或重置。

## 修复内容

1. **建好二层样板后，其他玩家和NPC持续断续移动**：远端动作缓冲原先永久采用收到过的最小时钟偏移。建造期间服务端物理帧计数落后于实际时间后，后续位置一直落在旧缓冲之外，只能短暂外推再停住；重进会重建缓冲，所以恢复正常。现在使用最近1秒的偏移下界校准，超过50ms的持续漂移会调整时间基准；呈现进度保持向前。保留150ms缓冲和120ms外推上限。本人预测和移动协议未修改。Godot在单帧物理步数达到上限时可能出现这种计数与实际时间的差异，见[引擎说明](https://docs.godotengine.org/en/4.6/classes/class_engine.html#class-engine-property-max-physics-steps-per-frame)。
2. **合法位置预览为红色，点击却能放下**：预览原先拿网络快照与待放置布局比较，而点击提交使用规范化后的私有草稿。两者数值表示不同，或另一地皮在本次编辑期间完成更新，都会造成不一致。预览现与提交使用同一份私有草稿及规范化结果。主人、修订号与地皮边界检查继续生效。
3. **新样板房看着开门却无法进入**：服务端恢复门状态时，会把没有历史记录的门当作关闭；客户端则按模型默认打开。现在首次注册采用模型声明的开关状态，并写入共享门状态。默认关闭的内门继续关闭，已有门状态继续保留。

## 在本机手动测试

双击项目下的 [`tools/本地双人建造测试.command`](../tools/本地双人建造测试.command)，或在项目目录运行：

```sh
python3 tools/local_multiplayer.py
```

入口调用本机Godot源码，启动一个独立账号服务、一个独立世界服务和两个游戏窗口，分别为兔兔与猫咪。每次使用全新的隔离账号和世界，目录在`.qa-artifacts/local-multiplayer-时间/`，不连接正式服，也不读取或保存真实单人进度。Godot路径可用`GODOT_BIN`或`--godot /path/to/Godot`指定。

两人可以各自在东岸购地，按F6进入建造。一人建好“两层楼阁”并确认完成后，切换另一窗口观察玩家和NPC走路、跳跃；继续进入建造检查物体预览与放置。房屋发布后，默认打开的外门可直接通过。关闭两个游戏窗口结束测试，也可在启动终端按Ctrl+C；入口只清理自己启动的进程。每次重开都是新测试世界。

普通Godot F5保持原有游戏入口。通过F5连接正式服时，服务端仍是旧版；本次门状态修复需要上述本地新服务端一起验证。

## 本次验证

Godot4.6.3 / Mac；共9组、1212项计数检查通过，另有两个独立客户端的本地入口自检。日志与汇总见[固定证据](evidence/multiplayer-building-fixes-20261117/summary.json)。

- `motion_buffer_rules`：125项。原逻辑在模拟丢失0.4秒、1.8秒服务端物理时间后持续出现停步；修复后0.08秒、0.4秒、1.8秒均在有限时间内恢复，稳定段无停步，时钟调整不倒退。也检查正常10Hz抖动、客户端暂停后的积压包、过期包和传送。
- `building_multiplayer_flow`：52项。两个真实账号/连接，分别完成99条记录的二层样板；施工草稿隔离、确认发布、另地皮更新、绿色预览与实际放置一致、越界红色与拒绝放置一致；新门默认开/关状态在双方和服务端一致，访客与本机角色实际穿过新建开门，无需先切换门；仍保留原增量复用和分片预算检查。
- `project_integrity` 468项、`building_multiplayer_rules` 59项、`release04_building_rules` 369项、`building_update_lifecycle` 1项、`building_controls` 34项、`opening_placement_flow` 59项、`doorway_step_flow` 45项。
- `python3 tools/local_multiplayer.py --check`：独立世界进程和两个独立Godot客户端均就绪，各看见1名另一玩家，然后退出并清理服务。

没有执行公网账号操作、版本导出、更新发布或部署。多人图形用例退出时仍有历史已存在的Variant池清理诊断；本地入口无界面自检退出有ObjectDB/资源清理诊断。通过的检查中没有脚本或Shader错误；这些退出诊断没有作为本次三个问题的修复范围。Windows实机、长时间满容量和真实弱网尚未覆盖，不能据此承诺所有设备始终60FPS。
