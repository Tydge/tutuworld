# 室内灯光与性能排查 · 2026-11-04

本轮仅修改并推送源码，未部署、发布或重建成品地图。测试用`--test`隔离进度；复现场景只读提取现有93条建造记录，在隔离副本中增加一盏立灯。公开证据不包含玩家存档或账号数据。

## 已修复的实际问题

- 床与座椅原先按`ActionAnchor`／`ExitAnchor`附近的单点显示E提示，床左侧贴墙时，从右侧或床尾无法互动。现在按家具局部占地计算最近边缘，随旋转/移动更新，墙体阻隔会拒绝互动；联机权威端也按同一规则校验。旧扩充测试直接指定`current_target`并传送到左侧挂点，漏掉了真实靠近流程；新用例使用实际E键，不预设目标。
- 原起身位置围绕固定左侧点扩大搜索，可能穿墙找到房间外的落点。现在记录交互前的位置，受阻时检查同一房间内的床/椅周边、墙体视线、真实地面与身体/头部净空，完全堵住时继续坐/睡；保留双人家具单一入口和空位自动分配。
- 立灯灯罩细杆会向墙壁和天花板投出放大的放射条纹。灯罩和细杆已关闭投影，保持外观及灯体/其他家具的正常阴影。
- 原交叉火焰片最深到局部`z=-0.36m`，穿过背板后表面`z=-0.31m`；从后方转动镜头可见穿插闪烁。修改后所有火焰顶点至少在`z=-0.094m`前，背板像素对照中火焰泄漏差值从2.337降为0。
- 火光从原约±7%改为平滑的约±26.5%亮度包络，20Hz只更新已有无阴影聚光灯的能量，不增加动态投影、粒子或位移。实际地板采样在较暗/较亮状态之间约有21%亮度差；减少动态效果设置保留稳定照明。

## 性能来源与实际优化

Apple M1 Pro / Godot4.6.3 / Metal Forward+，均衡档约200万3D像素、4×MSAA，UI保持原生。基线提交`722a70b`使用独立临时工作树；新旧各跑15个相同的时间路径（转镜头并在室内移动），关帧率限制与VSync，每项预热0.5秒、采样2.5秒。下表采用首轮正常条件；重复正常条件另保留在JSON。

| 模式 | 修改前帧中位ms | 修改后帧中位ms | 前→后p95 ms | 前→后总绘制次数中位 |
| --- | ---: | ---: | --- | --- |
| 自由避挡 | 21.66 | 20.73 | 31.34 → 30.64 | 1908 → 1728 |
| 自动俯视 | 16.13 | 15.51 | 25.05 → 24.98 | 1696 → 1509 |
| 自由完整 | 21.95 | 21.71 | 32.34 → 32.30 | 1778 → 1759 |

三种模式都可能超过60FPS的16.7ms帧预算；本轮改善并未消除复杂房间的所有掉帧。主要证据如下：

- **真实阴影与像素渲染是主要负担。** 新版自由避挡同一路径：保留全部光照时20.74ms，诊断性关闭局部阴影后15.83ms，关闭局部光照后12.65ms；正常条件约1,209次阴影绘制，关闭局部阴影后约561次。渲染像素临时减半后12.93ms，而绘制次数没有相应减半，说明像素相关渲染也占明显成本。关闭开关只用于诊断，产品保留主要遮光与投影。
- **避挡计算有重复工作，但不是主要耗时。** 单次完整探测CPU测得140.6→107.2微秒，约减少24%，绝非整帧提升24%。现在9个角色探测点一次生成，墙面/门扇的逆变换每段只算一次，同面已命中时跳过重复段，轻微变化约30Hz采样；淡入淡出仍逐帧更新。
- **自建墙面原先每帧重复提交全部材质参数。** 现在只有模式、相机所在墙侧或透明度变化才提交；自由完整模式正常转镜头时，实测未变化墙面的重复提交为0。空床的被子参数也停止无效逐帧更新。
- **远处室内灯具原先没有投影距离预算。** 现在使用引擎原生距离渐隐：投影14m起、10m过渡，光照26m起、10m过渡；无需为每盏灯添加脚本或物理射线。火光保持原有近范围、无阴影方案。配对场景自由避挡阴影绘制中位约1,412→1,209。
- **火光抖动控制器的CPU开销很小。** 600个模拟帧共200次更新，测试约0.3ms总CPU时间；火光仍有实际局部照明的GPU成本，不能把节流控制器耗时当成整个光源成本。
- 测量时启用了RenderingServer的GPU计时，但当前Metal返回0；记录为“不可用”，不能据此宣称GPU没有消耗。像素和阴影开关的对比支持渲染负担较重的判断。没有持续的大量管线编译，样本中通常0，少数场景首次出现1～2次。

详细配对数据：[旧版](evidence/indoor-fixes-20261104/performance-before.json)、[新版](evidence/indoor-fixes-20261104/performance-after.json)。CPU渲染提交时间和整帧墙钟时间分别记录，`TIME_PROCESS`含帧等待等影响，不作为纯脚本耗时。

## 后续值得优先做的优化

1. 给均衡档评估可选的阴影质量预算，优先限制远处、低贡献灯具及无关小部件的投影；必须保留墙体遮光、主要家具投影与双面装修效果。现阶段近距离主要投影仍保留，不能靠关闭全部阴影完成验收。
2. 如果目标是在更复杂布局稳定60FPS，评估带迟滞、缓慢过渡的3D动态分辨率，UI继续保持原生。像素减半诊断收益明显，但需要单独验收细节、闪烁与镜头移动清晰度。
3. 对固定城镇模块评估更细的几何/投影LOD和静态烘焙方案，分别验证昼夜；玩家自建和可移动家具继续采用动态方案。
4. 抗锯齿、SSAO和太阳阴影距离单变量实验见[补充采样](evidence/indoor-fixes-20261104/performance-detail.json)。这轮没有据短样本强制降低画质：降低MSAA或缩短太阳投影距离没有显示出足够稳定的整体收益，阴影灯数与像素预算更值得优先研究。

距离渐隐、遮光与投影开销的引擎约定参见[Godot Light3D](https://docs.godotengine.org/en/4.6/classes/class_light3d.html)、[灯光与阴影](https://docs.godotengine.org/en/4.6/tutorials/3d/lights_and_shadows.html)；计时含义见[RenderingServer](https://docs.godotengine.org/en/4.6/classes/class_renderingserver.html#class-renderingserver-method-viewport-get-measured-render-time-cpu)。

## 验证与边界

建造回归27组全部通过；额外通过城镇规则、交互修订、真实WebSocket三客户端双人座位、聊天/长椅和保存失败回滚。新增实际E键用例51项、立灯/火光/材质提交用例8项。固定住宅跨物种/昼夜/画质稳定性记录与日志索引见[证据汇总](evidence/indoor-fixes-20261104/summary.json)。

采样为短时顺序实验，现场仍有其他本地Godot进程；配对运行输出均为1920×1080，约200万3D像素。补充实验单独记录窗口尺寸，不混入配对幅度。未验证Windows/GPU分项时间、热稳定长测或所有容量上限叠加；固定地图未重生成，原音频采集用例退出诊断也未在本轮重新归因。
