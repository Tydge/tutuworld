# 多人和更新接口

**玉京扩展**　海岛城的 `travel` 接受目的地 `jade`，返程目标为 `city`。服务器的公共状态包含 `jade_build_layout`、六块地及 `jade_plot_` 和 `jade_source_` 前缀的田地与采集点。家具成品保存在角色库存。持有本人地皮施工租约时可发送 `make_furniture`，参数为 `parcel_id` 和 `item`。相同命令 ID 的重试返回原结果。发布布局时 `build_finish` 一起核对修订号、租约与家具余量，材料不足或成品超支保留原状态。[服务端回归](../tests/jade_multiplayer_rules.gd) · [正式接口版本](#公网入口)

适用版本为 **0.6.3 / build 15 / 网络协议 5 / 启动器 2**。联机需要当前构建号和协议号。已安装的启动器 2 可通过签名资源包升级。发布、备份和试服入口见[服务器运维](服务器运维.md)。

## 公网入口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | [健康检查](https://47.119.37.251/tutuworld/health) | 就绪时返回 HTTP 200 和 `{"ok":true,"version":"0.6.3","build":15}`。世界端口未监听时返回 503。 |
| GET | [签名更新清单](https://47.119.37.251/tutuworld/manifest.json) | 当前受信任构建、安装包下载地址和更新资源摘要 |
| GET | `https://47.119.37.251/tutuworld/releases/<version>/<file>` | 固定版本的 `manifest.json`、`city.pck`、`TutuWorld-macOS.zip`、`TutuWorld-Windows.zip` |
| WebSocket | `wss://47.119.37.251/tutuworld/ws` | 版本协商、账号、角色、多人游戏和聊天 |

账号服务的 `POST /register`、`/login`、`/resume`、`/logout` 供游戏服务通过回环调用。请求为 JSON 对象（最多 4096 字节），业务结果为 `ok` 与可选的 `message`；认证成功的内部结果含 `account_id` 和 `token`。公网客户端通过 WebSocket 请求这些动作，返回的认证结果移除了 `account_id`。令牌有效期为 7 天。

## 签名更新

清单外层为 `{"payload":"<JSON 字符串>","signature":"<Base64>"}`。先使用 [release_public.pem](../config/release_public.pem) 对原始 `payload` 的 UTF-8 字节验证 RSA-SHA256 签名，再解析内层 JSON。内层字段为：

| 字段 | 0.6.3 |
| --- | --- |
| `schema` | 1 |
| `build`、`version` | 15、`"0.6.3"` |
| `min_launcher`、`protocol` | 2、5 |
| `notes` | 本版本更新说明 |
| `pack` | 含 `url`、`sha256`（64 位十六进制）和 `bytes`（大于 0，最多 256 MiB） |
| `installers` | `macos`、`windows` 下载地址 |

更新资源下载后核对长度和 SHA-256，重启时再次验签和核对 SHA-256 后才挂载。实现见 [update_client.gd](../scripts/services/update_client.gd)、[update_trust.gd](../scripts/services/update_trust.gd) 和 [boot.gd](../scripts/boot.gd)。

## WebSocket 消息

每条消息是一个 **二进制** WebSocket 消息，负载为 GZIP 压缩的 UTF-8 JSON 对象。压缩包及解压结果上限均为 1 MiB。建立连接后先发送：

```json
{"type":"hello","build":15,"protocol":5}
```

服务端返回 `welcome` 或 `update_required`，两者带有 `build`、`version`。握手成功后可发送 `{"type":"ping"}`，收到 `{"type":"pong"}`。业务请求格式如下。

```json
{"type":"request","id":"unique-request-id","verb":"travel","args":{"destination":"icefield"}}
```

响应为 `{"type":"result","id":"unique-request-id","result":{"ok":true}}`。失败的 `result` 通常包含 `ok:false` 和中文 `message`。已入场的客户端可能先收到快照再收到对应结果。请求 ID 长度最多 128 字符。能去重的玩家写操作重试时应复用同一 ID 和参数。

### 客户端命令

| 前置条件 | `verb` | 主要 `args` |
| --- | --- | --- |
| 版本握手通过 | `register`、`login` | `username`、`password`；成功返回 `token` 和 `characters` |
| 版本握手通过 | `resume` | `token`；成功返回 `token` 和 `characters` |
| 已登录 | `characters` | 空对象；返回 `characters` |
| 已登录 | `create_character` | `name`、`species`、`starter`；成功返回 `character` ID 和新名单 |
| 已登录 | `join`、`leave`、`logout` | 分别为 `character` ID、空对象、`token` |
| 已入场 | `emote` | `id` 为动作目录中的 ID，运动包中的 `emote,emote_revision,emote_age` 同步给同图玩家 |
| 已入场 | `chat` | `text`，去首尾空白后最多 120 字，向已入场的全服玩家广播 |
| 已入场 | `travel` | `destination`，见下文 |
| 已入场 | `dress_resident` | `target` 是雪镇 NPC ID，`outfit` 为槽位到已拥有服装 ID 的对象 |
| 已入场 | `buy`、`sell`、`equip` | `buy/sell` 接收 `shop,item,quantity`；`equip` 接收 `slot,item` |
| 已入场 | `door`、`sit`、`talk`、`history`、`plant`、`water`、`weed`、`harvest`、`gather`、`refill`、`rest` | `target` 为交互对象；播种另带 `item` |
| 已入场 | `craft`、`eat`、`snack` | 制造使用 `target,recipe`，进餐使用 `target,item`，零食使用 `item` |
| 已入场 | `stand`、`wake`、`end_talk`、`cancel`、`unstuck` | 可用空对象 |
| 试染 | `tailor` | `target` 为试衣架，`item` 为已拥有服装，`design` 含 `pattern,color,accent`；`restore:true` 恢复原样 |
| 玉京坊印 | `jade_visit` | `target` 指向本栋案台，`moves` 记录本局操作。驿袋交接只需目标。服务端校验玩家位置和完成情况，已得坊印可重玩，每个角色只领一次首成谢礼。 |
| 雪镇互动 | `stamp`、`claim_trail`、`bake`、`brew_tea`、`warm` | `target` 为当前地图内可够到的印章架、图册、烤炉、茶具或蓄热炉 |
| 地皮操作 | `buy_land`、`build_begin`、`build_ping`、`build_finish`、`build_cancel` | `parcel_id`；续租、发布和取消带 `lease`；发布另带 `expected_revision,elements` |

`travel` 支持 `city → valley`、`city → icefield`、`city → jade` 及各自的返城航线。服务端检查角色已在出发码头、可从当前动作离开，并能在目的地安排安全落点；三条出城航线各扣 10 贝壳币，返城免费。位置和船票在同一保存事务内结算。

`dress_resident` 需在绒雪裁缝店与商人保持可交易距离。可传 `head`、`neck`、`body` 中的一部分，服务端验证服装和槽位后合并现有搭配。例如 `{"target":"SnowBaker","outfit":{"head":"pompom_cap_frost"}}`。传空对象恢复该居民的默认服装。已保存的搭配通过同图 NPC 的 `equipment` 广播，并写入 `world.json` 的 `world.winter_outfits`。

试染的两种颜色为六位 RGB 小写十六进制，纹样使用服装材质目录中的 ID。角色快照的 `clothing_designs` 以服装 ID 为键，运动包只广播已穿服装的试染数据。踏雪印章保存在角色的 `snow_trail` 中。烘焙与泡茶在动作完成后扣材料，取消时保留材料。旅舍使用现有 `rest` 和 `wake` 指令，床位通过目标 ID 区分。

### 移动、快照与广播

- 客户端发送 `{"type":"motion","generation":1,"inputs":[{"seq":1,"direction":[1,0,0],"running":false,"jump":false}]}`。`generation` 来自服务端，`seq` 在该代次内连续递增，单批最多 12 步。方向向量按世界 X/Y/Z 排列，服务器仅接收水平输入并限制长度。场景切换和位置重置后使用新的代次。
- `snapshot` 含 `state`、`job`、`locks`、`care_history`、`doors`、`epoch`、本人 `movement`，以及 `building_protocol:1`。冰原建造客户端可检查 `winter_building:true`。建筑修订号在 `state.building_revision`。海岛城布局使用 `state.build_layout`，冰原布局使用 `state.icefield_build_layout`，玉京布局使用 `state.jade_build_layout`。同图同一修订的重复快照可省略布局，换岛会发送目的岛的完整布局。客户端按布局字段分别缓存。施工玩家继续收到同图玩家动作，居民动作和周期性全量快照在离开建造时恢复。施工边界、制作结果及已开放的建筑会主动同步。有效的 `build_ping` 直接返回续约结果。
- 服务端 `motion` 含 `tick` 和同图 `actors`。玩家行带 `id,map,position,velocity,yaw,generation,ack,equipment,animation_speed,ice_inertia` 等；`map` 取 `city`、`valley`、`icefield`、`jade`。NPC 行带 `npc:true`、`equipment` 及动作、位置等字段。冰面带惯性的玩家松开方向后仍可能滑行。
- `chat` 广播带 `id,name,text,map`，客户端仅在同图角色头顶显示气泡；生产完成的 `event` 通过 `event` 字段携带结果。

权威实现和参数校验见 [world_server.gd](../server/world_server.gd)、[building_service.gd](../server/building_service.gd)、[local_authority.gd](../scripts/services/local_authority.gd) 和 [packet_codec.gd](../scripts/services/packet_codec.gd)。
