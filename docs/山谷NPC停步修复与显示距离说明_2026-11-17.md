# 山谷NPC停步修复与显示距离说明

后续状态（2026-11-18）：相关修复已随0.4.2正式发布部署，见[当前发布与清理记录](0.4.2_发布与清理记录_2026-11-18.md)。下文保留当时阶段记录。

日期：2026-11-17。以正式0.4.1/build8为基准；本次修复源码，未发布新版本、未更新正式服务。正式版仍有旧逻辑；本地联网验证必须启动本机源码的隔离服务器，普通F5连接正式服不会应用服务器修复。画面距离、阴影、地图和玩家数据均未更改。

## 停步原因与修复

正常漫游中捕获溪桥西侧卡点`(-12.04554, 3.221917, 13.67664)`：最近的导航格`(-12, 14)`本身可行走，但两者之间有一条不满足坡地足部支撑条件的窄带。实时移动正确拒绝迈入；旧脱困一直朝最近格前进，重新选目的地后的第一格仍相同，因此兔子持续原地重试。交互独立运行，所以仍可对话；客户端重进不能修复权威端位置。

`scripts/city/npc_driver.gd`现在在脱困时检查16个方向，每个方向检查前方1、4、10厘米的真实通行与地面支撑，选择可走的短转向，再继续寻路。水平加速改为二维向量加速：旧X/Z独立加速使斜向脱困的第一步变成45度，仍撞回不可走的窄带。保留碰撞、坡度、岸边支撑与速度限制，不靠瞬移或关闭碰撞脱困。额外方向查询仅在脱困时执行。

## 显示距离及取舍（本轮未修改）

以下同时核对生成器与保存的`valley_map.scn`，见[场景读取结果](evidence/valley-npc-recovery-20261117/rendering-ranges.json)。世界单位按米使用；植被距离按相机到空间批次包围盒中心计算，不是逐棵树到玩家的距离，因此可能整组切换。

| 内容 | 当前范围 | 投影 |
| --- | --- | --- |
| 近景树 | 0～约67米 | 精细模型、有实时投影 |
| 远景树 | 约67～245米；远山树到320米 | 简化模型、无实时投影 |
| 草 | 约45米 | 无实时投影 |
| 林下细节/河岸植物 | 约65～70米 | 无实时投影 |
| 太阳阴影 | 最大100米，约80米起渐隐 | 树在约67米切到无投影版本，可能更早失去树影 |

山谷扩大到216×212、约原四倍面积，含271棵近景/幼树、220棵远山树、36,728簇草。设计用共享原型、空间批次、远景简化和距离限制，控制模型及实时投影开销，照顾M1 Pro和“均衡”约200万3D像素的帧率预算；[历史测量](水体与连续山谷重做_2026-11-17.md)不是所有硬件的帧率保证。这是客户端画面预算，与多人网络传输无关。“均衡/原生”目前只改变3D分辨率，不改变这些距离；相机远裁剪为1200。

当前取舍偏保守，过渡处理也未完成：实际场景的植被`visibility_range_fade_mode`全为0。该模式的距离margin是避免临界处反复切换的滞回区间，不产生视觉渐变，所以树形、草与投影会突然变化。[Godot 4.6几何实例说明](https://docs.godotengine.org/en/4.6/classes/class_geometryinstance3d.html#enum-geometryinstance3d-visibilityrangefademode)、[包围盒距离说明](https://docs.godotengine.org/en/4.6/tutorials/3d/visibility_ranges.html)。

后续建议先消除突变（近远轮廓连续、渐变过渡、批次大小），再分层拉远树影并增加远处低成本明暗层次，按硬件提供植被/阴影独立档位。直接大幅拉远全部实时阴影，会增加绘制对象，也让固定阴影贴图覆盖更大范围、降低近处细节；需配对画面与帧耗时评估。[Godot太阳阴影距离说明](https://docs.godotengine.org/en/4.6/classes/class_directionallight3d.html#class-directionallight3d-property-directional-shadow-max-distance)。具体方案等与用户讨论后实施。
