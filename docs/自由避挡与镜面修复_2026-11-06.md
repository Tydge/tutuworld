## 原因与修复

原实现用共用材质的`opacity`执行抖动淡出，到终点再将共用网格`visible=false`。反射相机使用同一World3D，因此既读到相同的淡出参数，也看不到已关闭的网格。镜面原生墙体遮挡体又跟随主镜头淡出启停，进一步把本应完整的反射房间打开。

现在将第19个渲染层（位18，`1<<18`）保留给反射相机。主相机排除该层；反射相机包含该层并继续排除镜面本身所在的第20层。自由避挡过渡时，`home_surface.gdshader`按`CAMERA_VISIBLE_LAYERS`仅对主镜头执行透明度裁切；完全隐藏的网格和窗玻璃仍存在，只转入反射层。离开自由避挡时恢复原渲染层。自建房屋和预置房屋使用同一可见性帮助函数；自动俯视、建造剖切和楼层显示保留原规则。[Godot 4.6的相机层着色器变量](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)支持这个区分。

反射中的实墙遮挡体保持稳定。原生遮挡体在World3D中共享，不能用这些完整墙继续裁剪可穿墙的主镜头，因此正常游玩的自由避挡关闭主viewport的这组原生遮挡裁剪，镜面viewport仍启用。自由完整与建造模式恢复原逻辑；退出场景恢复原viewport设置。删除整栋建筑也清理遮挡体。主画面仍有正常视锥裁剪、深度遮挡和原有阴影。

掉帧的主要已复现原因是`building_world.gd`将所有材质参数更新放在一起：每次`alpha`变化，都会再次调用`set_shader_parameter("building_cut_mask",同一纹理)`。这不是重新加载墙体或重建地图，也不是每次隐藏必然要承受的开销。[Godot 4.6.3材质源码](https://github.com/godotengine/godot/blob/4.6.3-stable/servers/rendering/renderer_rd/storage_rd/material_storage.cpp#L2169-L2184)在纹理参数赋值时不比较旧值，仍标记纹理脏；[绑定更新路径](https://github.com/godotengine/godot/blob/4.6.3-stable/servers/rendering/renderer_rd/storage_rd/material_storage.cpp#L1093-L1115)会释放并重建uniform set。现在过渡帧只更新透明度，固定配置按变化提交，遮罩仅在纹理对象改变时绑定。ImageTexture内容更新不需要再次绑定。

遮挡体动态变化也有成本：[Godot说明](https://docs.godotengine.org/en/4.6/classes/class_occluderinstance3d.html)运行时隐藏/移动会触发后台重算。本轮将自由避挡的反射遮挡体启停次数降为0；单因素实验确认，重复纹理绑定才是本次固定镜头中约5.5ms额外耗时的主要来源，不能将所有历史长帧归因于遮挡体。

## 验证方法和边界

Mac / Apple M1 Pro / Godot 4.6.3 / Metal Forward+，3024×1890窗口、均衡档3D比例约0.592、主视图4×MSAA、反射2×MSAA。隔离`--test`进度，全城镇加4面真实墙、1面目录镜子和1扇窗。相机固定，玩家探测点在墙两侧交替，避免镜头移动、镜面显露和纹理扩容混入切墙开销。关闭VSync和FPS上限，关闭自动渲染循环，每个process_frame仅一次force_draw，以完整墙钟帧计时；脚本CPU开销单列，不充当总帧耗时。

预热后采样960帧，每80帧切换一次目标；分别统计稳定、淡变、网格层切换帧。`--rebind-mask`仅在测试中重新加入原重复绑定行为，允许在同一份修复代码、同一场景上做单因素对照。正常玩法没有该分支。

相同最终场景的单因素对照如下；P99不是最长帧。

| 条件 / 帧类别 | 中位ms | P99 ms | 最长ms | >16.7ms / 帧数 |
| --- | ---: | ---: | ---: | ---: |
| 重新加入旧重复绑定 / 稳定 | 7.281 | 7.628 | 8.565 | 0 / 828 |
| 重新加入旧重复绑定 / 淡变 | 12.801 | 13.594 | 13.603 | 0 / 121 |
| 重新加入旧重复绑定 / 隐藏/恢复端点 | 7.290 | 12.958 | 12.958 | 0 / 11 |
| 修复后 / 稳定 | 7.262 | 7.693 | 27.437 | 2 / 740 |
| 修复后 / 淡变 | 7.260 | 7.475 | 7.505 | 0 / 209 |
| 修复后 / 隐藏/恢复端点 | 7.279 | 7.333 | 7.333 | 0 / 11 |

重复绑定使淡变中位耗时从7.260ms增至12.801ms，约多5.54ms。修复后的稳定帧仍有2个长帧，最长27.437ms；淡变与端点帧没有超预算。本次不把短路径P99通过写成全程零掉帧。两组着色器流水线新增编译均为0，修复组原生墙体遮挡体启停也为0。原始旧实现另复现镜内像素平均误差约0.503；它不含后来加入的窗，只用作缺陷复现，不作为同场景性能对照。

验证结果和逐帧数据见[evidence/wall-occlusion-20261106](evidence/wall-occlusion-20261106/summary.json)。固定对照中，镜内完整墙参考图与自由避挡完全隐藏状态图的平均及P99通道误差均为0，半透明过渡也通过同样图像对照；主视图实拍确认可以穿过被隐藏墙看到室外。玻璃、预置房屋、模式恢复和删除建筑另有检查。

本轮解决可避免的重复材质绑定和错误的跨相机可见性。淡变、显示更多墙后物体、真实阴影与镜面渲染仍有正常成本，不能保证任意房屋或所有显卡零长帧。多镜面既有的独立平面预算、首次分配和共享阴影差异继续见[多镜面验收](多镜面反射优化与验收_2026-11-06.md)，不因本次修复宣称已解决。

相关回归10组、最新选定检查共1375项通过，另运行重复绑定单因素诊断。逐组计数与日志见同一证据汇总；既有多镜面性能未达标项没有隐藏或降低验收线。

## 复现入口

```sh
python3 tools/dev.py test wall_occlusion_flow --windowed --timeout 180
python3 tools/dev.py test wall_occlusion_performance --windowed --timeout 180
# 单因素对照；复现旧重复绑定的成本，不用于性能达标验收
python3 tools/dev.py test wall_occlusion_flow --windowed --game-arg=--rebind-mask
python3 tools/dev.py test --suite mirrors --windowed --timeout 240
```

严格性能入口检查稳定、淡变和隐藏/恢复端点三类的P99均小于16.7ms，不降低验收线。功能入口不因硬件帧率差异而删掉镜内像素、原生遮挡体稳定性或模式恢复断言。

代码入口：`scripts/building/building_world.gd`、`scripts/city/seabreeze_home.gd`、`interior_view.gd`、`city_world.gd`、`mirror_reflections.gd`、`mirror_occluders.gd`、`assets/shaders/home_surface.gdshader`；回归为`tests/wall_occlusion_flow.gd`，已加入`mirrors`和`building_walls`套件。
