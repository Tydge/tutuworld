## 日常检查与恢复

`systemctl status tutuworld-world tutuworld-auth tutuworld-backup.timer`查看运行状态。世界每10秒及关键结算保存，退出角色也保存，临时文件+flush+备份+原子替换；异常由systemd重启。账号使用SQLite WAL、scrypt和令牌哈希，令牌有效7天。健康接口同时检查游戏端口，但验收还需实际WSS握手，不能只看HTTP200。

`tutuworld-backup.timer`调用私有备份，账号库通过SQLite备份API读取，世界JSON独立备份。恢复时先停两个游戏服务，留故障数据副本，恢复同一备份批次的世界和账号并核对所有者为`tutuworld`。不能用试服替换正式世界，也不能只拷SQLite主文件漏掉WAL中的变更。

公共世界`epoch=1793584800.0`；`clock_alignment.version=1`已保存，现实整点对应游戏00:00、半点12:00。更新/重启必须保留，**不再运行align-clock或重建起点**。工具中的align-clock仅供未校准的新世界一次性维护，已有标记时不再调整；不能改服务器系统时钟或开放客户端调时。

客户端每30秒在本机日志聚合FPS、RTT、未确认输入和校正次数；服务器有玩家时每30秒记录人数、积压输入及主循环平均/最长间隔。不记录聊天正文。分析卡顿需结合客户端帧时间与网络指标，单看服务端无报错不足以判断流畅。

## 构建与发布顺序

在新的版本号/build下构建，禁止覆盖现有已发布目录（包括0.3.3）。先同步`release.gd`、`project.godot`、原生boot基准build及本次更新说明，确认launcher/协议兼容性，再执行：

```sh
# 1. 构建；Windows必须提供官方Microsoft.Direct3D.D3D12 1.618.5 nupkg
python3 tools/build_release.py --godot /path/to/Godot --output /path/to/artifacts --d3d12-sdk /path/to/sdk.nupkg --part all

# 2. 上传服务端候选包，启动隔离试服；不切正式服
python3 tools/deploy_multiplayer.py prepare --ssh-key /path/to/ssh-key --artifacts /path/to/artifacts --engine-zip /path/to/godot-linux.zip

# 3. 完成隔离试服验收后，仅暂存客户端产物和签名清单
python3 tools/publish_release.py --stage-only --artifacts /path/to/artifacts --signing-key /path/to/private-key --ssh-key /path/to/ssh-key

# 4. 切换正式服务（短暂停服、备份、启动并轮询新版本健康）
python3 tools/deploy_multiplayer.py activate --ssh-key /path/to/ssh-key

# 5. 确认WSS/数据保留后，推广已核对的同一份更新清单
python3 tools/publish_release.py --promote --artifacts /path/to/artifacts --signing-key /path/to/private-key --ssh-key /path/to/ssh-key
python3 tools/deploy_multiplayer.py status --ssh-key /path/to/ssh-key
```

工具从`release.gd`读取版本/build/协议。prepare使用隔离数据和临时试服服务；activate停旧服务后快照正式数据、切current并检查健康，再加载Nginx，最后停试服。若任何一步失败，先检查服务、current指向和日志，不能继续推广清单或删除released标记强行覆盖。回退需成对考虑服务版本与签名清单，不能直接覆盖已有玩家的新进度。

publish先核对远端文件SHA256再固定版本目录；promote核对暂存manifest摘要后原子切换根清单，保留manifest.previous.json。只公开`city.pck`、两个客户端zip和签名清单；`server.pck`、私钥、账号库与世界状态不能公开。`city.pck`已含完整双地图。

Windows原生包首选D3D12，随包附Agility SDK 1.618.5运行库/许可，NV/AMD独显偏好为1；Mac为x86_64/arm64通用临时签名，未公证。Windows实体机和双显卡运行仍未验收。两端新安装默认全屏/60/均衡，已有设置保留。

`config/network_ca.pem`包含官方ISRG Root X1/X2，出处见[Let's Encrypt证书](https://letsencrypt.org/certificates/)；保留主机/IP、有效期与证书链验证。发布工具需要OpenSSL、SSH/SCP、导出模板，Mac签名需要macOS codesign。

## 本地多人和更新测试

用例不会自动启动账号服务。先在独立终端运行隔离账号服务：

```sh
TUTU_STATE_DIR="$PWD/.qa-artifacts/auth-local" TUTU_AUTH_PORT=18892 python3 server/auth_service.py
```

`multiplayer_rules`自启游戏服18893、`chat_seat_rules`自启18902，均使用上述账号服务；`interaction_revision_rules`自启18901且无需账号。`production_multiplayer_rules`另用账号18912和游戏18903，启动账号时相应改端口。一次运行一组。

`multiplayer_live`、`multiplayer_client_flow`、`movement_latency`还需独立世界服务：

```sh
TUTU_STATE_DIR="$PWD/.qa-artifacts/world-local" TUTU_AUTH_PORT=18892 TUTU_GAME_PORT=18891 \
  /path/to/Godot --headless --path . --script res://server/main.gd
```

这些用例创建测试账号，`--test`不隔离外部服务器数据，只对本地/隔离试服运行；`TUTU_TEST_ENDPOINT`可改WS地址。弱网代理`tools/latency_proxy.py`默认监听18894、连接回环18891，参数见`--help`。用完只关闭自己启动的进程。账号服务单测：`python3 -m unittest discover -s tests -p test_auth_service.py`。

`update_integrity`需`--game-arg=--fixture --game-arg=/path/to/manifest.json`，`update_rules`需`TUTU_TEST_MANIFEST`；均应使用真实签名的测试清单。`update_download`实际下载，工具要求显式`--allow-network`。`multiplayer_public`只读核对公网TLS与入场拦截，不建账号。
