# 多人建造与封闭施工

2026-11-12的源码阶段记录；当时未发布。后续于11-13按用户授权随0.4.0/build7/协议4正式上线，见[后续修复、部署和更新验证](0.4_修复与发布记录_2026-11-13.md)。以下日志保留当日固定结果。

## 已确认的玩法

- 只允许地皮主人编辑。其他玩家可在施工结束后参观、坐卧、料理及用餐。
- 进入建造前由服务器核对角色身份、地皮归属、地图、距离和当前互动。四块地皮沿用立板旁E确认购买与100币测试价。
- 开工后整块地皮封闭；已经在里面的其他玩家被分别送到外侧真实地面上的安全位置，并收到提示。坐卧、工作中的访客也先取消动作、退回实际预留并释放占用，不在施工区域留下角色。
- 施工中有围栏和标牌，移动预测、实体碰撞及服务端移动/交互校验共同阻止进入；尝试靠近进入时提示正在施工。
- 修改只留在建造界面的本次草稿中，保留原有撤销、重做、样板、楼层与外观操作。其他玩家继续看到上一次完成的建筑。
- 点击“确认完成 · 开放地皮”后，服务器重新校验全部记录及地皮版本，原子保存，再准备地图更新，完成后开放。Esc/F6提供完成、继续建造和放弃修改的选择。放弃或未提交时断线，保留原建筑；已提交成功的完成事务继续落盘与更新。
- 客户端每10秒续期施工；未提交的施工60秒没有续期则释放。施工凭证只发给本人，不广播、不写入世界存档。重启不恢复未完成草稿。

## 地图更新方式

不切换场景，不重新加载城镇，不重建地图资源。原角色、地图和未修改的建筑节点继续使用。客户端按模块的几何签名和位置比较差异，仅准备新增、移动或替换的模块。

新模型、门窗网格合并、房间连通搜索和物理对象挂接按约3毫秒的脚本工作预算分帧执行。新部件准备时隐藏，地皮保持封闭；最后集中切换显示，旧部件随后分批回收。尚未准备完的客户端继续保持本地围栏，避免走进缺少碰撞的房屋。服务端也采用分帧准备，多个完成请求按顺序处理；不执行仅用于绘制的网格合并，保留真实碰撞、动作挂点和导航。导航的局部重采样也按预算分帧进行。

门窗使用与实际模型一致的缓存，房间搜索可暂停续算；普通单人建造继续使用同一套即时算法。预算以单个不可再分步骤为下限，脚本分片耗时与最终切换耗时分别记录；这些数字不等同于整帧耗时或所有设备稳定60FPS。

常规快照只在完成版本变化或新连接时携带建筑布局，施工草稿不会按操作上传。服务器只合并当前地皮的记录，保留其他地皮的最新版本；物件ID冲突及墙体、台面依附由权威端重新整理。客户端不能提交归属、价格、迁移豁免或其他地皮的依附关系。

## 事务与兼容

建筑布局、地皮归属及地皮版本放在公共世界存档，不复制到角色记录。旧服务器存档缺少这些字段时补空值，不清空原有角色、作物、资源或时钟。单人存档、备份及地皮进度仍独立。

撤离访客需要的落点先全部确定，再改变角色；保存失败恢复所有受影响角色、动作、锁、余额及施工状态。完成保存失败时保持旧地图和施工草稿，允许重试。重复购买或完成请求不重复扣款、不重复增加地皮版本。

## 样板房墙镜

按本轮追加要求，“温馨小屋”和“两层楼阁”各新增一面真实墙镜。温馨小屋安装在起居区隔墙内侧；两层楼阁安装在一楼厨房隔墙内侧，原二楼镜子继续保留。目录布局现分别为29条和99条；只在两套JSON末尾追加一条镜子及递增编号，原记录完整保留。仅影响以后从目录新建的样板，不改写已存在的玩家房屋。

两套样板在四个朝向均验证墙面支撑、合法放置与原有地皮范围；真实摆放/旋转流程和联机发布使用更新后的目录。截图：[温馨小屋墙镜](evidence/building-multiplayer-20261112/screenshots/single_one-wall-mirror.png)、[两层楼阁厨房墙镜](evidence/building-multiplayer-20261112/screenshots/two_storey-wall-mirror.png)、[双客户端完成的两栋房屋](evidence/building-multiplayer-20261112/screenshots/two-online-houses.png)。

## 验证入口

```sh
python3 tools/dev.py test building_multiplayer_rules --timeout 180
# 实际账号服务必须使用隔离目录与18919端口；不要连接生产账号库。
TUTU_STATE_DIR="$PWD/.qa-artifacts/building-auth-local" TUTU_AUTH_PORT=18919 python3 server/auth_service.py
python3 tools/dev.py test building_multiplayer_flow --windowed --timeout 240
```

规则检查使用隔离世界；真实联机流程使用本地WebSocket、独立账号、两个客户端和两栋各99条记录的二层样板。核对封闭/撤离提示、私有草稿、确认后公开、同一场景与角色持续存在、未修改模块的身份复用和分帧更新。另覆盖已放置床椅、餐桌、料理台与服务端重读。

本轮按影响范围分批通过21组验证，带计数的检查共2660项；最终联机套件含59项服务端规则、35项真实双客户端流程和场景销毁中的更新取消。最新两栋99条样板的客户端更新复用142个原部件，准备跨100次让帧，最后切换约7.14毫秒，最长已测脚本分片约18.02毫秒。单件改色只替换和回收一个对象。这里记录的是脚本耗时，不是完整帧或GPU耗时。

楼梯旧测试场地与后来增加的公共立板重合；只把隔离测试场地移到空地皮，保留全部36项实走条件并通过。部分Godot测试退出仍打印ObjectDB/PagedAllocator回收提示，不据这些用例宣称长期无内存泄漏。

本轮最终验证数据见[固定证据](evidence/building-multiplayer-20261112/summary.json)。Windows实机、异地弱网、满四层及所有容量上限叠加仍需另外验证，不能据当前本机样板检查推断全部场景无卡顿。
