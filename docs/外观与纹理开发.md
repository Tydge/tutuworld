# 外观与纹理开发

更新：2026-11-06。本地工作树已接入，尚未发布。服装、家具布料共用纹理目录与染色接口；新增内容首先改资料与资产，涉及新造型或新渲染方式时才扩展代码。

## 分工与入口

| 位置 | 职责 |
| --- | --- |
| `data/appearance/materials.json` | 唯一材质目录：稳定ID、名称、适用部位类别、使用范围、排序、图案文件与各场景尺度 |
| `data/appearance/clothing.json` | 服装通用默认值、款式默认值、具体商品与初始服饰清单；默认值→款式→商品依次覆盖 |
| `data/furniture_appearance.json` | 家具部位ID、模型匹配、材质类别、可选限制与整套配色预设 |
| `assets/fabrics/` | 可重复铺贴的灰度图案；SVG与PNG使用同一接口，AI图保留来源与提示词 |
| `scripts/appearance/material_catalog.gd` | 读目录、按类别/用途筛选、校验资料，不持有场景或玩家状态 |
| `scripts/appearance/clothing_catalog.gd` | 展开服装资料，校验款式、图案、颜色与初始服饰引用 |
| `scripts/appearance/fabric_material.gd` | 按需缓存图案资源，创建独立染色材质，统一写入布料着色参数 |
| `assets/shaders/fabric*.gdshader*` | 普通/双面布料，共用采样与配色逻辑；衣物裁剪通过参数控制 |
| `scripts/building/appearance.gd` | 家具部位映射、恢复、应用与旧整件染色兼容；床被保留原有形变着色器 |
| `scripts/building/structure_catalog.gd`、`surface_edit.gd` | 结构纹理、房间批量匹配及独立内外墙面；不进入服装布纹目录 |
| `scripts/building/appearance_panel.gd` | 从目录生成部位/材质选项，预览与保存分开 |
| `scripts/ui/fabric_swatch.gd` | 同图案与配色的小图，最多缓存64种；没有逐种花纹的绘制分支 |
| `scripts/city/outfit.gd` | 服装几何与Rig挂点；材质来自共用接口 |

`scripts/city/fabric_library.gd`保留为旧路径兼容入口，继承新的布料实现；新代码使用`scripts/appearance/`。GameData仍是游戏商品入口，其服装内容由ClothingCatalog提供。没有引入第三方运行依赖。

纹理与Shader按需共用；每个可染色实例保留独立材质，避免改一件时影响其他家具或服装。商品目录与部位资料只读，实时调色不改原始材质。缩略图仍使用真实模型与独立外观缓存。

## 增加一种现有类型的布料图案

1. 在`assets/fabrics/`添加一张可平铺灰度图。黑色表示布底色，白色表示花纹辅色，灰色为混合。优先让图案在原始尺寸就可连续铺贴；检查边缘与图案分布。细线/规则形状适合SVG，手绘印花可用PNG。
2. 只在`materials.json`登记新条目，例如本次实际加入的条纹：

```json
"stripes": {
  "name": "细条纹",
  "renderer": "fabric",
  "families": ["fabric"],
  "uses": ["furniture", "clothing"],
  "order": 50,
  "texture": "res://assets/fabrics/stripes.svg",
  "scale": {"clothing": 2.5, "furniture": 1.8, "quilt": 1.8}
}
```

3. 在Godot中导入资产，再运行下方检查。满足类别/用途条件的家具部位自动显示新选项，普通布料、形变被子和小图都读取同一记录，无需加纹理名称判断分支。`scale`越大，单位长度内重复越多、花纹越小；不同尺寸的衣物/家具可以分别定尺度。

已有渲染方式为`original`原始材质、`solid`纯色、`surface`结构纹理、`fabric`灰度双色图案。木纹/石材沿用结构Shader。完整彩色印花、法线/粗糙度贴图或分别染花瓣/叶片等需要新渲染或遮罩接口，不能仅换灰度图后假定已支持。

家具界面现在分别提供底色与花纹色；波点/条纹/格纹/花叶和AI雏菊均可调。原始材质有花纹时也会读取原有辅色，纯色时隐藏第二选项。`appearance[部位].accent`为可选字段，旧记录缺省时维持原奶油色/原始辅色；保存、撤销、重置、取消预览及小图均包含它。新保存的双通道外观按灰度遮罩正常混合：黑色为底色，白色为花纹色，不再额外混入22%底色；灰色细节与抗锯齿仍有自然混合。没有显式花纹色的旧记录保留灰度×0.78的原始对比度。服装配置可分别设`color`和`accent`，尚无衣领/袖口等通用独立编辑界面。

## 增加服装、家具与部位

使用已有服装造型：在`clothing.json`的`items`加一项，填写稳定商品ID、`style`、名称、颜色与图案；槽位、价格、说明等可沿用款式默认值，特殊值就地覆盖。商品自动进入云朵服装店、试穿、购买、衣柜与三物种挂点流程。默认初始服饰由`starters`显式列出，新增商品不会自动扩大奖励。

新增服装造型：先在Outfit/Rig实现几何，再加入款式默认值；新印花不需要复制模型。新服装需检查兔、猫、熊猫。价格规则同时维护在[04策划](策划数值与机制/04_物品商店与服装.md)。

当前目录44种家具、129部位；新增挂画/壁镜/挂钟/壁灯/收纳推车/调味罐共14部位，镜面反射表面不参与染色。新增餐桌的桌架/桌面、餐椅的椅架/软垫共4部位。新增料理台包含柜体、台面/瓷砖、木饰、五金、挂巾与食材6个部位。人字拼、水磨石、铃兰纹，以及厨房鼠尾草花砖/奶油青瓷釉砖均由共用Shader按世界坐标生成，无额外大图；两款厨房纹理对应`home_surface` pattern7/8，以导数抗锯齿并给釉砖较低粗糙度。

新增家具：在建造目录与生成器增加物体，并在`furniture_appearance.json`定义部位。每个部位至少包含`id/name/family/colors`；`colors`首项是默认色，既有模型还用它作旧颜色选择器。部位允许材料默认按`family`筛选；必要时用`materials: ["original", "solid", "dots"]`缩小范围，不会放开不兼容类别。

新模型推荐在每个可编辑Mesh上直接设置固定标记：

```gdscript
mesh.set_meta("appearance_part", "frame")
```

显式标记优先于原名称/颜色/高度选择器。旧模型选择器继续兼容，未知部位会进入检查结果，不能忽略。部位分组后再合批，避免不同部位合成无法单独编辑的Mesh。灯泡、火焰、水和接触阴影等效果不作为染色部位。

存档继续使用原来的部位ID、材质ID和颜色字段，布局现为schema4，楼层字段与外观部位独立。外观编辑本身沿用原子检查点与取消恢复；本轮经用户授权的壁炉位置调整另见[真实存档核对](墙面陈设与楼梯出口验证_2026-11-06.md#真实存档与样板)。27件原服装的最终商品字段由独立兼容快照核对，旧纹理、部位ID与初始9件服饰保留。已发布ID不得随意删除或改名；需要改动时先做迁移。渲染时未知服装图案回退纯色；存档中未知家具材质会明确拒绝，不能用它代替迁移。

## 本次扩充实践

| ID | 名称 | 来源 | 服装商品入口 |
| --- | --- | --- | --- |
| `stripes` | 细条纹 | SVG矢量图案 | 鼠尾草绿细条纹马甲 |
| `dots` | 奶油波点 | SVG矢量图案 | 莓果红波点围裙 |
| `daisies` | 雏菊印花 | 内置image_gen生成及接缝、分布修改 | 鼠尾草绿雏菊围裙 |

三种均可用于现有布料家具部位。旧27件加3件新商品，共30件服装。雏菊按用户确认保留当前较密版本，后续可替换同一ID的资产或调整配置尺度。

AI原图保留不改像素，运行时只引用项目内[daisies_ai_v2.png](../assets/fabrics/daisies_ai_v2.png)；完整生成与两次修改提示词、原始输出和SHA256见[来源](../assets/fabrics/daisies_ai_v2.source.json)。最终导入限制512×512、启用mipmap、无损纹理存储，当前读回的RGB含mipmap数据约1MiB，未做有损显存压缩。原PNG大小、磁盘导入产物和显存纹理字节是不同口径。此规则针对当前细节图案，大面积环境图仍按各自导入策略压缩。

## 验证入口

```sh
python3 tools/dev.py test --suite appearance --windowed
```

包含目录与引用校验、27件旧服装快照、资料自动扩充探针、16块图案分布/接缝检查、真实家具面板/被子形变/缩略图、商店试穿、三物种、存档和原有相机/移动/恢复。新增商品无需更新写死的服装总数断言。素材首次加入后须先用Godot导入，再运行图形检查。

操作与室内视角见[建造模式](建造模式.md)，当前验证范围见[验证基线](验证基线.md)。
